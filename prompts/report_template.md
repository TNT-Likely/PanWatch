# Hermes cron 报告输出规范(借鉴 daily_stock_analysis)

> 借鉴 https://github.com/ZhuLinsen/daily_stock_analysis 的 `templates/report_markdown.j2` 结构。
> 目的:让所有 cron 报告(盘前/盘中/盘后/复盘/盯盘)格式统一,可读性高,直接推送 WeCom 也无需重排版。

## 关键规范

### 必含章节(不可省)
- 📌 核心结论(操作信号 + 一句话)
- 📊 数据透视(价格/量能 — 至少含现价 + 量比 + 换手率)
- 🎯 作战计划(理想买/止损/止盈 + 仓位建议)
- 🛡️ 阶段决策(何时操作 + 何时再查)

### 选含章节(数据有就加)
- 📰 信息面(有新闻/舆情就加)
- 🧩 信号归因(归因有数据就加权重)
- 📜 历史对比(用户已关注 ≥3 天才有意义)

### emoji 规范
| 类别 | emoji |
|------|------|
| 多/加仓 | 🟢 🆕 🎯 🔵 ✨ 📈 💼 |
| 震荡/观望 | 🟡 👁️ ⏸️ |
| 空/减仓 | 🔴 🛑 🚨 ⚠️ 📉 |
| 数据/报告 | 📊 📈 📉 📌 📰 💭 📜 📚 |
| 时间 | ⏰ 🕐 📅 |
| 行动 | ✅ 🔍 💡 🎯 |

### 表格对齐(GFM)
- 表头用 `|---|` 对齐
- 列数控制在 2-4 列(过宽移动端难看)
- 数字右对齐(可选)

### 排版禁忌
- ❌ 不用一级标题 `##` 进到表格内(层级混乱)
- ❌ 不写超过 3 层缩进列表
- ❌ 不堆 emoji(一个章节 ≤ 3 个)
- ❌ 不写绝对日期(用 `今日/明日/本周` 而非 `8月7日` — 模板可复用)

## 适用报告类型

| 报告类型 | 强制章节 | 选填章节 |
|---------|---------|---------|
| 盘前涨价推理 | 核心结论 + 作战计划 | 数据透视(早盘)/ 信息面 |
| 盘后复盘 | 核心结论 + 数据透视 + 历史对比 | 信息面(隔夜) |
| 盘中监测 | 核心结论 + 作战计划(立即) | 阶段决策(高频) |
| 持仓日报 | 核心结论 + 作战计划 + 阶段决策 | 信号归因 |
| 预测复盘验证 | 核心结论 + 历史对比 | 数据透视(实际 vs 预测) |

## 与 daily_stock_analysis 的差异

| 维度 | daily_stock_analysis | PanWatch(借鉴版) |
|------|----------------------|------------------|
| 模板引擎 | Jinja2 + Python | 直接 Markdown 文本(LLM 输出) |
| 报告生成 | 程序填充字段 | LLM 生成 + 模板约束 |
| 翻译 | labels.yaml 多语言 | 单中文(直接写) |
| 数据获取 | 多数据源 + 实时接口 | MCP 数据源 + 已知字段 |
| 输出渠道 | WeChat/企业微信/图片 | WeCom 在线文档 + 报告中心 |

## 复盘(每月一次)

1. 收集本月所有 cron 报告
2. 对照实盘决策是否一致
3. 哪些章节用户看了 / 跳过了 → 调整章节优先级
4. 哪些数据用户追问 → 补充字段
