# 助手能力基础

[English](assistant-capabilities.md)

行情工具将来源时间与获取时间分开保存，返回供应商、可核验的来源时间、报价交易日、市场状态与时效。未知时间、休市报价和旧交易日报价不能证明当前实时价格；原始涨跌幅保留在来源字段中，不冒充今天涨跌。

报价明确标为供应商快照，未验证收盘已确认。午休、休市或延迟状态不能证明它是官方收盘价、最后成交价或来源将在某时刻更新；需要有状态收盘触发的请求仍不支持。

依据区分外部数据、工具发现和本地查询快照。工具发现显示执行时间；股票标的查找、自选、市场日历、通知配置、能力检查、价格提醒读写回执及监控健康显示原查询快照时间，不套用行情时效标签。旧对话使用原执行时点恢复展示，不把历史结果更新成当前数据；真正缺少来源时间或已经过期的外部依据仍保留警告。历史研究及混合持仓估值不因本地存储就被当作新数据。

`check_watch_request` 从本轮原始用户请求提取明确标的、自选／持仓范围、支持的相对期限、条件类型与渠道，并列出能力缺口。期限锚定任务创建时刻，审批恢复不重新计算。这是有边界的解析器，不能保证理解任意自然语言；名称不明确需查股票库，未知要求需澄清。暂不支持收盘确认、均线、连续交易日、穿越事件或新闻发布触发，也不建立持续研究任务。

“再试一下”等整句明确重试沿用前一用户请求及其条件，保留原到期时间。引用在模型上下文压缩前确定，只使用用户原话；遇到更新的话题就停止回溯。无法定位原请求时要求澄清，不能把空解析当作已支持，也不能把重试解释为接受盘中替代方案。

提醒支持价格、涨跌幅、成交额、成交量、量比的平铺 AND/OR 组合，以及到期、启用渠道 ID、交易时段、冷却、每日上限和一次／重复模式。审批展示拟保存参数，成功写入与后续查询返回完整实际规则。冷却为 0、每日上限为 0 会保留，后者表示不限次数。渠道保存不代表实际消息送达；成交量／额沿用来源单位，不猜测换算。

只读工具可查询自选库、按市场区分的历史建议（包括过期观点）、上下文快照及明确保存市场的历史报告。缺少市场的旧报告单独计数。CN 公告提供发布时间和来源链接，全文读取先核验标的与公告编号；全文缺失或截断明确披露。HK/US 监管公告尚未覆盖。

持仓诊断使用正式注册的只读工具和宿主权限策略，保存内部调用参数、字段、来源时间、失败与步骤 ID。结果卡将各项主要诊断判断关联到对应依据。内部读取最多 16 次，并受任务工具调用上限约束；宿主工具截止时间为 120 秒，整个任务仍为 180 秒。

## 生产路径评估

明确标的的创建操作核对股票代码与市场；混合 AND/OR 需要嵌套逻辑，不能平铺改写。能力检查执行完成不代表提醒已经创建，结果详情保留尚未实现的条件。

按项目 `panwatch-local-delivery` 技能准备独立环境并启动服务。通过正常设置接口配置 QA 模型，添加启用的合成飞书渠道，不填真实收件端，不设为默认渠道。评估仅访问该 run 的 loopback 服务，只读核对该 run 的数据库：

```sh
.venv/bin/python scripts/evaluate-assistant-runtime.py --run '<私有 QA run>'
```

默认十个场景覆盖延迟工具发现、真实任务 worker/runtime、批准前不写入、完整 DB 回读、重复审批、拒绝、不支持条件、真实 SSE 客户端断开与顺序回放，并补充日常表达的 OR 规则、过期历史观点、实际公告正文及判断与证据关联的持仓诊断。首次启动前准备按市场保存的过期合成研究和合成持仓。合成对话和两条提醒会保留供检查，人工验收期间不要复跑覆盖环境。999999 价格阈值仅用于避免触发合成提醒，不是投资建议。

`--case` 可选择用例；脚本模型用 `--mode replay`，不能算真实模型通过。退出码 `0` 为全部必需真实模型用例通过，`1` 为已执行断言失败，`2` 为未完整执行（包括仅回放或仅选部分用例）。报告不含凭证。实际通知送达、任意自然语言、其他模型和真实网络断网需分别验收。

旧 `tests/eval/run_eval.py` 不覆盖生产 runtime，缺少模型时现在退出 `2`；`--allow-incomplete` 仅显式允许部分本地检查。脚本模型单测是契约检查，不能证明真实模型质量。报告保留失败执行，按层级分别记录结果。

PASS 仅表示列出的断言通过。每个场景另记用户目标：不支持请求仍未完成，拒绝审批仍未创建提醒；防护通过不能记作这些能力已经支持。


## 监控健康与持久投递

价格提醒页面展示扫描心跳、最近检查和成功时间、连续数据/检查失败、停用、到期、每日触发额度，以及分渠道投递状态。助手通过只读 `get_monitoring_health` 查询同一持久记录。休市和冷却属于等待，不计为成功检查或数据故障。日额度计触发次数，0 表示不限；AI 金额硬预算不在此能力内。

新命中、站内事件和每个目标渠道的待发记录在同一事务提交。独立 worker 每 10 秒检查队列，发送租约 90 秒、单次超时 45 秒，失败按 30 秒指数退避，最多 5 次，耗尽后可在命中历史确认重试。成功渠道不会随失败渠道重发；单次规则触发停用后仍会投递该次事件。配置被删除或停用时记录为渠道不可用；恢复原渠道后可确认重试。没有启用默认渠道时保留站内事件，并提示为后续提醒配置渠道。

事件编号在重试中保持一致。接收端缺少幂等接口时，发送成功但确认未落库的崩溃可能产生重复，语义为至少一次投递；“渠道已接受”不证明接收人已读。旧命中没有分渠道记录，结果未知时明确显示，升级不会自动补发旧通知。队列不保存渠道密钥，公开接口只返回固定错误码。

健康目前覆盖价格提醒，不覆盖其他自动化、持续研究任务或 AI 金额预算；默认预计扫描为 60 秒加最多 20 秒调度抖动，持续延迟会提示检查服务。
