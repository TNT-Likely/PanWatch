# 时区规则

[English](timezones.md)

PanWatch 区分四类时间。界面语言不决定时区。

| 时间类型 | 规则 | 示例 |
| --- | --- | --- |
| 存储时间点 | UTC；API 带 `Z` 或明确偏移 | `16:00+08:00` 与 `08:00Z` 是同一到期时间 |
| 用户显示与输入 | 自动使用浏览器时区，避免共用偏好互相覆盖 | UTC 浏览器显示、编辑到期时间为 `08:00` |
| 后台执行时间 | 使用部署 `TZ`，任务调度与通知静默时段共用 | `0 9 * * 1-5` 表示部署时区工作日 09:00 |
| 市场交易日期 | 使用交易所时区，独立于用户与服务器 | 美股交易日期使用 `America/New_York` |

## 显示和编辑

设置页分别显示浏览器时区和后台执行时区。任务预览转换为浏览器时间；
调度输入明确标注执行时区。提醒到期输入采用浏览器时间；未修改到期字段时，
保留原时间点、秒数和夏令时重复小时。夏令时开始时跳过的当地时间不能提交。
新输入的夏令时结束重复小时使用浏览器选取的较早一次；已有到期时间保留原来的那一次。

首页“今日提醒”带浏览器 IANA 时区查询。后端分别生成当天与次日当地午夜，
按 UTC 的 `[起点, 终点)` 查询，正确覆盖 23、25 小时日期。
未传时区的旧客户端继续采用部署日期；明确传入无效时区返回错误。

提醒列表与股票详情入口都将原始到期时间交给共享表单。外部 API 和助手工具的到期字符串
必须带 `Z` 或明确偏移；无时区字符串会被拒绝，避免默认为 UTC。内部无时区的 UTC datetime
保持兼容。模拟盘平仓时间转换为用户当地日期；交易日期和报告日期继续按日期值处理。
研究元数据区分报告日期与转换后的 `generated_at` 生成时间。

新闻发布时间带明确偏移。东财和新浪提供的中国当地时间按 `Asia/Shanghai` 解析后转为 UTC；
雪球、财联社的 epoch 时间戳已代表时间点，无须修改。交易日期、K 线日期、报告日期
是日期值，不能作为用户本地时间点转换。

## 后台执行

需要 UTC 调度与静默时段时，在部署环境设置 `TZ=UTC` 并重启服务。
有夏令时的地区使用 `America/New_York` 等 IANA 名称。
保留现有 `Asia/Shanghai` 默认值，升级时不会移动现有任务。
更改 `TZ` 前应核对 cron：两个时区的 09:00 对应不同时间点。
浏览器访问与切换语言不会改写后台任务。

Docker 支持 `docker run -e TZ=UTC ...` 和 Compose `environment: { TZ: UTC }`。
镜像包含时区数据，不会自动推断宿主机时区。更改环境变量后重建容器，保留数据卷。

## 回归保障

`pnpm --dir frontend check:timezones` 和前端构建会拦截对已知时间点字段直接截取字符串，
以及写死非 UTC 的显示时区。这是语法检查，不是完整的数据流分析。
交易所时区应来自市场映射；仅用于日期值星期计算的 UTC 格式化属于明确用途。

时区 CI 验证股票提醒完整入口、未修改微秒、本地输入、午夜边界与夏令时。
浏览器用例覆盖 UTC、上海、纽约、加尔各答、加德满都、基里蒂马蒂；后端协议也会在
UTC、上海和纽约部署时区运行。新增时间编辑入口时补充入口测试，使用字段前先明确
它代表时间点、当地钟表时间还是市场日期。

## 兼容性与后续范围

SQLite 读取 UTC 字段时丢失偏移，助手 DTO 在 API 边界补回 UTC。
现有带偏移的 API 返回值有效且保持兼容。历史无时区新闻和来源记录缺少完整来源语义，
本次不会猜测后批量改写。

用户手动覆盖显示时区、每个任务独立编辑执行时区，需要额外产品范围与迁移。
研究和策略中的 `date.today()` 默认值需要按市场逐项审查，不能当作用户显示偏好替换；
本次保持这些日级聚合规则。
