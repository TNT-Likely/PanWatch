# 真实验收与证据

按本次需求生成场景，不固定功能范围。先记录目标、模块、源码/产物身份、环境和明确不覆盖的平台。

## 业务场景表

每项记录：id、对应需求、前提、实际动作、预期结果、实际结果/断言、状态/原因、用户目标是否完成、源码/构建/run 身份、命令/退出码、相对证据路径。标明正向功能或防护用例；拒绝、取消和无副作用不能代替正向业务结果。用真实日常表达补充脚本中提示工具名和操作步骤的场景。

层级分为 unit、integration、runtime-replay、live-api、live-ui、live-model、manual。固定数据、协议模拟与真实上游各自记录。手工操作注明无命令。每个主要行为有直接结果断言，不以文案出现代替持久化验证。

| 修改范围 | 正常路径 | 按风险补充 |
|---|---|---|
| 页面／设置 | 正常入口操作→保存→回读→刷新 | 取消、重复、错误、亮暗色、桌面/窄屏、滚动/键盘 |
| Assistant／AI | UI→实际 task runtime→注册工具→审批→结果/DB | 拒绝、重复审批、SSE 重连、模型/工具超时；真实 invocation |
| 行情／研究 | 来源字段→API→页面/证据 | 时效、市场状态、缺失、口径冲突、单位/币种 |
| 提醒／调度／通知 | 创建→实际规则→调度命中→发送记录 | 组合、到期、渠道、时区、重复、重试；送达独立验证 |
| 持仓／模拟盘 | UI 写入→DB 数量/成本/关系→读取 | 取消、非法输入、重复、重启；模拟盘不作实盘验收 |
| API／鉴权／MCP | 实际协议客户端→鉴权→接口→DB | 权限、非法参数、重复；函数直调不能代替协议 |
| 迁移／存储 | 合成旧 DB→正常迁移→新数据 | 幂等、备份、失败恢复；只在隔离数据演练 |

## 快速回归

查看当前脚本和受影响测试，选择相关模块；记录实际命令及结果。先检查测试是否初始化默认 DB、读取现用 .env 或调用外部服务，有此风险则在隔离副本执行。

后端用项目解释器运行受影响 pytest 文件。pytest 默认不发通知，不自动增加 `--notify`。前端变更执行：

```sh
pnpm --dir frontend check:ui
pnpm --dir frontend check:i18n
pnpm --dir frontend check:market-colors
pnpm --dir frontend run test --run <受影响测试文件>
pnpm --dir frontend build
git diff --check
```

模块参数按实际变更选择。测试成功后的扩大或重复检查应有新变更、失败或未解疑点作为依据。

技能和工具变更执行：

```sh
python3 -m unittest discover -s .agents/skills/panwatch-local-delivery/scripts -p 'test_*.py' -v
python3 -m unittest discover -s scripts/agent_skills_tests -p 'test_*.py' -v
```

既有 `tests/eval` 要检查实际入口；legacy 适配器、脚本模型和 mock 结果不能证明生产 runtime。AI 证据包含真实工具列表、task/event/approval/invocation 身份、实际 DB 结果和模型身份；脱敏后再公开。

## 实服验收

1. 独立浏览器 context/profile 登录本次 origin。先读取可用浏览器工具说明，不清理用户现有浏览器数据。
2. 通过可见控件完成动作，经正常读取接口和私有 DB 查询核对对象 ID、数量、字段、关系和原对象是否变化。
3. 故障只影响 QA 进程，注明 API 503、客户端断开、网络模拟或真实断网；不得混称。
4. AI 需求至少验证适用的生产 runtime + 真实模型路径。凭证、预算或依赖不可用时，将对应层级记为未执行；模型、工具和数据失败分别记录。
5. 正常入口刷新并重启 QA 服务，复用同一 DB/产物，核对页面和持久化状态；进程/DB 存在仅作辅助证据。
6. 复跑保留前次失败退出码、截图和版本。后续独立复核通过不改写先前失败；人工验收期间不重置数据。

逐项 `PASS / FAIL / 未执行`。无法执行时继续其他可执行层级并报告具体阻碍，不生成假截图、假输出或预期数据填补结果。
