# 验收结束后的资源清理

关闭服务不等于释放磁盘。验收／任务结束、用户要求清理或核实 PR 已合并后，执行完整清理；仍待人工验收时仅保留一套明确交接的最终环境。被替代的中间 run 及时归档结果后回收，不等所有 PR 合并才清理。

## 先确定归属与保留项

- 准备 run、模型任务、临时工具链或报告验证副本时记录其绝对路径、run ID、关联任务／PR和用途。共享依赖与只读借用的解释器明确标为保护资源；不可仅凭目录前缀、年龄或占用大小认领。
- 清理前列出精确目标，结合任务记录、manifest 所有权标记、源码／提交身份及当前进程核对。对有歧义、其他任务仍引用或用户要求保留的资源跳过并说明，不进行全局扫盘删除。
- 默认保留一份最终脱敏报告／ZIP及hash、必要失败摘要和清理回执，置于 run 外的 `.docs/` 或指定本地交付目录。验证复制后的大小、hash和可打开性，再删除原副本。已封存包不原地修改；另写生命周期回执更新“环境已关闭／已删除”。
- 失败证据只保留支撑结论所需的退出码、版本、断言、错误摘要及必要截图；先做脱敏，不为保存失败而复制整套原始日志、数据库、行情、模型产物和缓存。凭证、token和浏览器状态不进入报告。
- 用户在最终 QA 内新增的数据如需继续使用，先明确保留范围；未获清理授权前不销毁人工验收数据。用户明确要求清理全部该任务测试资源时，说明测试数据库随之删除；原项目数据与非测试数据不在范围内。

## 先停服务，再删资源

1. 按[隔离与运行](isolation.md#关闭测试环境)核对并卸载本任务服务管理器 job，停止身份匹配的服务、训练／下载 worker、报告预览和专用接收端。PID复用、端口被其他进程接管或身份不符时不杀进程，记录并进一步核对。
2. 确认不会自动重启、没有进程仍使用目标路径；记录关闭结果到 run 外。服务停止失败、worker仍写入或归属不清时，不删除相关目录。
3. 对每个已验证目标执行显式、限定路径的删除，不使用宽泛 glob，不递归删除仓库、工作区、HOME、系统临时根或共享缓存根。拒绝目标 symlink和路径越界；目录内依赖 symlink只能解除自身链接，不跟随到外部。
4. 回收本任务的隔离源码、副本数据库／行情、node_modules／构建产物、模型／MLflow缓存、临时日志、凭证、工具链下载及报告解压／渲染验证副本。借用的项目 `.venv`、共享包缓存、用户浏览器profile、原业务数据库和其他任务资源不删除。额外资源只有明确归属且无其他引用才纳入。
5. 本次创建的托管 worktree 若已无保留需求，先确认改动已提交／推送或可恢复保存，再使用托管归档工具；不手动递归删除 worktree。用户要求保留的功能 workspace 不归档。
6. 验证目标已不存在、原服务端口未被本任务监听、管理器 job 已卸载。记录处理项、跳过／失败项、保留报告位置与回收大小。删除不可由产品恢复的临时数据库／缓存须在交付中说明；最终报告及远端源码可恢复，不代表已删除的 QA 数据可恢复。

## 存储度量与结束条件

- 删除前后记录目标占用与文件系统可用空间。APFS克隆、压缩、硬链接和其他进程会影响实际回收；区分“目标占用估算”与“可用空间实测变化”，不把 `du` 总和直接当作已释放字节。
- 不把资源仅移入同盘垃圾箱／归档目录后称为释放空间；不清空用户整个垃圾箱。保留精简证据后删除已授权的可再生测试资源。
- 清理失败应保留清单并说明原因，不反复扩大删除范围。完成说明须包含停止了什么、实际删了什么、保留什么，以及是否可恢复。
- 仅更新 skill／文档时运行对应工具测试，不为证明流程额外建立全量业务环境；小型合成生命周期测试结束也要清理自身临时资源。
